## 四、运行方法
### 前置条件
1. 已经在原项目根目录执行过 `uv sync` 安装了所有依赖
2. 本作业位于原项目根目录下的 `homework/` 文件夹
3. 项目结构如“三、项目结构”图所示

### 启动命令
1. 激活原项目虚拟环境
```bash
source .venv/bin/activate
```

2. 添加依赖
```bash
uv add flask
```
> 如果用uv run触发了 openai-whisper 的构建问题，请用以下指令安装作业专属依赖（仅需执行一次）
```bash
.venv/bin/python -m pip install flask
```

3. 启动聊天服务
```bash
uv run python homework/web/app.py
```

> 如果用uv run触发了 openai-whisper 的构建问题，直接使用python命令即可正常运行。
```bash
python homework/web/app.py
```

> 运行后如果终端出现如下红色警告：
```plaintext
WARNING: This is a development server. Do not use it in a production deployment.
```
这是 Flask 开发模式的标准提示，完全**正常**。


4. 访问系统
打开浏览器访问：http://127.0.0.1:5000

5. 退出方式
终端按下 Ctrl + C 即可安全关闭 Flask Web 服务。

## 八、难点与总结
### 开发核心难点
1. 跨目录模块导入：作业目录独立在`homework`，需要处理Python路径，安全调用顶层`src/core/decision_engine`，不能破坏原有项目结构。
2. 低耦合隔离设计：全部作业代码封闭在homework文件夹，新增、删除、修改均不影响原Rak-Runtime底层AI逻辑。
3. 全局异常容错：覆盖空输入、接口超时、模块缺失、网络异常等各类场景，保障Web服务持续可用。
4. 多环境兼容：同时支持uv与原生pip两种依赖安装方式，适配课堂不同运行环境。

### 对应解决方案
1. 通过动态追加项目根路径至系统环境变量，实现跨层级模块导入；
2. 完全独立目录架构，作业与主项目代码物理隔离；
3. 多层try-except捕获各类运行异常，前端返回人性化提示；
4. 提供两套安装命令，兼顾教学环境多样性。
